# Phase 7 性能报告

> **所有帧率目标都处于“待实机测试”状态。** 容器里没有 GPU，浏览器使用 SwiftShader（CPU 软件渲染的 WebGL 2），一帧需要 150–800 ms，这个数字不能推断任何真实 GPU 的帧率。

### 采取的措施（按收益排序）

1. **石皮完全覆盖时跳过透射通道（第 01–03 幕）。**
   - three.js 只要场景里有透射材质，就会把整个场景再渲染一遍作为透射背景。
   - 第 01–03 幕原石全被石皮覆盖，透射本应为 0，所以在材质上把 transmission 设为 0，这一整遍渲染就省掉了。
   - 这个过程中发现了一个 **v1.0 以来就存在的着色器错误**：石皮、棉絮、裂隙对透射的遮挡写在 three.js 设置 `material.transmission` 之前，因此被覆盖，从未生效（石皮一直有约 45% 透光，显得发灰）。现已移到正确位置。
   - 修正之后跳过透射通道在视觉上是精确等价的。为了保持已经确认的观感，石皮反照率乘以 0.8，各工件的透射基值略微提高，前后对比见视觉报告。
2. **第 03 幕放大镜改为无透射玻璃。** 它是第 03 幕唯一的透射物体，仅仅为了折射镜片就让整个场景多渲染一遍。改用反射加半透明的材质后，第 03 幕从 64 / 119k 降到 45 / 81k。
3. **地形网格的行沿台阶边缘排布。**
   - 每一行就是某一级台阶上某个固定位置（包括边缘的起伏），岩面处密、平台处疏。
   - 网格从 192×139 降到 168×65，三角形 54k → 22k。
   - 同时修正了旧网格在 +x 一侧略微伸出方形边界的问题。
4. **矿场里的原石使用低细节版本。** 在矿场中原石只有约 40 像素高，换成同一形状、同一材质、同一石头坐标属性的 4.5k 三角形版本（原为 27k）。离开矿场（缩放 > 0.3）后切回高细节版本。
5. **碎石、灌木和几何体复用。**
   - 小碎石改用 20 面的共享几何体，只接收阴影、不投射阴影。
   - 巨石保留 80 面并投射阴影。
   - 卡车上的石料复用巨石几何体。
   - 灌木改为单团树冠。
6. **`rbox()` 圆角分段跟随半径。** 2–8 mm 的倒角（半径 < 0.012）用 1 段，不再用 4 段；每个小零件少约 900 个三角形，惠及所有设备。
7. **阴影分级。** 最低画质档（阴影贴图 1024）关闭小物件的投影：巨石、树干、灌木。第 01 幕从 78 / 128k 再降到 75 / 123k。该档本来就把像素比降到 0.75，这部分的收益在 GPU 填充率上，上述数字统计不到。

已评估、暂不采用：
- **合批：** 矿场每个刚体组内同材质的网格已经合并（Phase 7.2）。再跨组合并会破坏挖掘机的关节层级。
- **把地形排除出阴影投射：** 台阶自身的投影是体积感的主要来源，不值得为它牺牲。

## 分析

- **第 01 幕（矿场）是主要成本：** draw calls +34%（86 → 115），三角形 ×2.4（197k → 480k）。
  - 第 02 幕在镜头远处仍会看到矿场，三角形也增加了 88%。
  - 第 01 幕各对象的三角形（单次绘制）：

    | 对象 | 三角形 |
    |---|---|
    | 极坐标地形 | 54k |
    | 原石 | 27k |
    | 侧面 | 11k |
    | 灌木 | 11k |
    | 碎石 | 10k |
    | 树冠 | 7k |

  - 地形、灌木、碎石和树冠会画三次：阴影、透射、主通道。
- **其他工位基本持平（±10%）：** 新增的门缝、螺栓、油缸等细节，由 `mergeByMaterial()` 合并抵消。
  - 第 02、03、06 幕的 draw calls 反而下降了 15–21%。
  - 第 08–09 幕的 draw calls 增加 8–24%：多出来的是机身细节在阴影通道里的绘制。
- **纹理：** 新增 6 张 128×128 的程序化 DataTexture：拉丝粗糙度 ×2、砂轮颜色和法线 ×2 组，另有一张摄影棚环境贴图（PMREM）。全部在启动时生成，**不需要下载任何文件**。
- **着色器程序：** 最多 49 个（v1.0 为 45）。多出的是地表材质和带纹理的金属、砂轮变体。
- **显存稳定性：** 12 幕循环三次，第二、三轮结束时几何体、纹理、程序数量相同。由回归测试“GPU memory stops growing…”验证，结果见 `PHASE7_VISUAL_REPORT.md` 的测试部分。
- **加载：** 发布构建的 JS 从 v1.0 的约 645 KB（gzip 约 177 KB）增加到 683 KB（gzip 191 KB），即 +38 KB（gzip +14 KB）。启动时额外的计算：生成地形网格与烘焙 AO（每个顶点采样 24 次高度）、生成纹理、生成 PMREM。在 SwiftShader 下加载到首帧的时间没有变长（桌面 10.3 s → 8.4 s；受机器负载影响，波动较大）。

## 如果真机帧率不达标（更新于 Phase 7.7）

Phase 7 初版列出的措施中，以下几项已在 7.7 完成：
- 灌木单团化
- 地形网格降密度（改为沿台阶排行）
- 低画质档关闭小物件投影

还没有采用的措施，按顺序为：

1. 低画质档关闭地形的投射阴影：阴影通道再减少约 22k 三角形，但台阶会失去自身的投影。
2. 移动端降低透射通道的分辨率，影响第 04–12 幕。three 0.170 没有现成开关，需要升级 three 或自行实现。
3. 移动端为切片和手镯准备低细节几何。

在拿到真机数据之前，这些措施都**不会启用**。
