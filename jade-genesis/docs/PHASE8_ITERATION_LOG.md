每轮按 Inspect → Implement → Screenshot → Compare → Test → Refine 进行，先修最严重的布局缺陷。

## 第 0 轮：检查与基线

- 对照用户的两张 iPhone 实机截图分析根因，见 `PHASE8_PLAN.md` 第 1 节。

  - **844×390 横屏：** 首页的“开始旅程”“自由探索”在屏幕外。

## 第 3 轮：扁宽区域

- **问题：** 320 上抽屉打开后，可用区域约为 320×168，又扁又宽。构图沿用桌面的纵向覆盖范围，原石的上下边超出了这块区域。
- **处理：** 宽区域的纵向覆盖从 0.9 提高到 1.15。手机竖屏仍由横向覆盖决定，不受影响。
- **横屏原石“仍被遮挡”的复核：** 用数值探针确认构图确实向左移动了；截图里的遮挡只是因为过渡还没结束就截了图（截图工具只等了 6 帧）。截图工具改为抽屉操作后等 16 帧。
- **结果：** 320、390、横屏打开抽屉时，原石都完整可见。

## 第 4 轮：触控目标与细节

- 展厅灯光按钮、速度按钮、声音按钮、视角提示原来是 33–36 px：触屏设备（`pointer: coarse`）上统一提高到 44 px。
- 320 宽时抽屉标题只保留阶段名，避免折行。

## 第 5 轮：测试与修正

| 发现 | 根因 | 处理 |
|---|---|---|
| 抽屉测试失败（底边读到 1211 px） | 测试在 0.28 秒的滑入动画中途测量 | 测试改为等位置稳定后再断言（`expect.poll`） |
| 抽屉测试点“暂停”失败 | 测试用 `goTo(…, false)` 跳转，此时没有在播放，按钮是“播放” | 改为点播放键，断言播放状态确实切换了 |
| 关闭后的布局检查认为抽屉按钮“在屏幕外” | 检查在滑出动画中运行 | 等抽屉完全隐藏后再检查 |

以上都是测试本身的时序问题，界面行为正确。

## 第 6 轮：桌面退化（P1，已修复）

- **发现：** 桌面 before/after 像素对比显示控制栏一行有 0.6–0.8% 的差异。放大后看到，新增的“知识”和“更多”按钮出现在了桌面控制栏上。平板也一样。
- **根因：** `.know-btn, .more-btn { display: none }` 与后面的 `.round { display: grid }` 权重相同，后者覆盖了前者。
- **修复：** 提高选择器权重（`.controls .know-btn`）；新增测试“regular layout keeps the v1 dock”。
- **结果：** 桌面首页、第 01、06 幕与 v1.1.1 **像素完全一致**；其他状态的差异 ≤ 0.4%，只在随时间变化的水流区域。
- **测试任务：** 当时正在运行的测试链基于有问题的构建，已停止，修复后整体重跑。
