### 测试发现并已修复的缺陷

| 缺陷 | 原因 | 修复 |
|---|---|---|
| 跳转进度后，状态里的阶段名仍是上一帧的 | 阶段名取自“最后一次渲染”的进度 | 改为由进度直接计算的纯函数 `phaseAt()` |
| 快速按下 `1` 再按 `T`，`T` 被忽略 | 键盘处理读取了界面缓存的工位，而缓存要下一帧才更新 | 界面改为发送 `toggleTorch()` / `step()`，由 App 读取当前真实状态 |
| 截图拍在镜头滑动途中 | 截图函数没有等镜头到位（产品行为正常：镜头约 1 秒内平滑移动） | 截图前先把导览镜头对准目标 |

开发阶段发现并修复的问题见 `ITERATION_LOG.md`。

## 无障碍与操作

- 所有按钮都有可读名称（`aria-label`），开关类按钮带 `aria-pressed`，工位切换使用 `role="tab"`。
- 进度条是原生 range 控件，带 `aria-valuetext`（阶段名 + 百分比）。
- 工位变化通过 `aria-live` 区域播报。
- 键盘：空格、←→、1 / 2、R、T、Esc。焦点有可见轮廓。
- 触屏目标不小于 44 px；支持 `prefers-reduced-motion`。
- **未验证：** 真实屏幕阅读器（VoiceOver / NVDA）下的体验。
